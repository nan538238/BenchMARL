# 区域防守战术建议可行性试验（诊断版）

这个试验回答一个窄问题：在同一组红方轨迹和同一套蓝方底层规则控制器下，提供特权的高层防守方向建议，能否提高区域守住率？它不训练 MAPPO、不使用 VMAS，也没有真人参与。正结果只能说明这个玩具任务存在信息介入空间，不能作为论文中的人机协同效果。

## 运行

在服务器 `~/BenchMARL` 中，更新功能分支并激活已有环境后运行：

```bash
python -m unittest discover -s test -p test_area_defense_pilot.py -v
python examples/area_defense_pilot.py --split ood --episodes 200 --seed 100 --budget 2 --output outputs/area_defense_pilot/ood_seed100
```

此脚本只使用 Python 标准库，因此也可在本地仓库测试。输出 `episodes.csv` 保存每个场景的三个配对结果；`summary.json` 包含成功率、平均请求数、相对无介入组的配对成功率差和按场景重采样的 95% bootstrap 区间。`--output` 必须给出项目内目录，以免误写其他位置；如果同名输出文件已存在，脚本会拒绝覆盖，请为每次试验使用独立目录。

## 三种条件

- `auto`：只根据蓝方可见范围内的红方位置选择“守三路”或“集中守某一路”。无请求。
- `oracle_all`：每 10 步由掌握未来 25 步红方路线的特权指挥员发出指令；每次决策都计一次请求。这个设定是乐观诊断，不是现实人类能力。
- `oracle_budget`：默认沿用 `auto`；仅当 oracle 指令不同且还有预算时覆盖，默认每局最多 2 次。它没有学习何时请求，不能代表拟投稿方法。

所有条件复用完全相同的控制器、捕获规则、初始状态和预生成红方轨迹。红方轨迹不随蓝方动作反应，因此这还不是自适应对抗试验。任务奖励仅为守住 `+1`、失守或超时 `-1`；主要指标是逐局守住率。输出中 `wins_from_intervention` 和 `losses_from_intervention` 分别记录同一场景因介入而翻转为成功或失败的次数。

`train` 集有集中、分散、佯攻三类轨迹；`ood` 集有后期换路、错峰集中、混合轨迹。这两个标签只用于该诊断脚本，不构成最终论文的严格分布外测试定义。开发中已经查看过两个集合上的结果；若要做发表用的未见对手评估，必须另建并冻结真正未见的对手族。

## 判读与下一阶段

若 `oracle_budget` 对 `auto` 的配对增益稳定为正，可以继续开发 VMAS 区域防守场景、意图条件 MAPPO 和部署时可见信息的模拟指挥员。若区间跨 0，结论是证据不足；若特权 oracle 稳定无增益，先检查指令集、动力学和底层执行能力。初版自主基线接近 100% 成功，有天花板效应，因此本版在训练场景上提高了红方速度、缩小捕获半径并延长捕获冷却；这些参数在看当前 OOD 结果前已固定。不要根据 OOD 结果继续调环境参数以制造正结果。

正式实验必须冻结同一套意图条件策略，在配对场景上比较无介入、真实可观测建议、预算触发方法；报告多训练种子、胜负、请求数、延迟和信息成本。真人效果需要真人研究单独验证。
